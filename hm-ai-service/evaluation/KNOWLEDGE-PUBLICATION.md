# 知识发布、版本与访问控制

本文对应当前代码的发布契约。服务端信任受控发布清单和网关登录身份；向量索引、用户提示与模型返回都不能决定访问权限或有效版本。

## 发布清单

在线默认使用`HMDP_AI_KNOWLEDGE_RESOURCE=shared`，所有实例从MySQL当前发布指针读取同一份不可变快照。命名空间由部署端的`HMDP_AI_KNOWLEDGE_NAMESPACE`指定，客户端不能选择。`classpath:knowledge/customer-service-v1.json`与`file:`保留为显式离线／受控验证模式；[文件目录挂载](../../deploy/knowledge-publication.compose.yml)只适用于该模式，不能提供跨实例一致性。

已有MySQL环境先执行`deploy/mysql/add_ai_knowledge_publication.sql`补建AI自己的三张表；新Docker数据卷启动时会自动执行该迁移。迁移不删除业务数据。发布前需在本地被忽略的`.env`配置`HMDP_AI_KNOWLEDGE_PUBLISH_TOKEN`并重建AI容器使环境变量生效；该凭证只注入AI服务，不能提交到Git或贴入会话。未配置时发布管理接口始终拒绝。

管理端点为`GET/PUT /internal/knowledge/publication`，同时要求内部共享凭证和专属发布凭证。普通用户登录不授予发布权限；元数据接口不导出正文。可在仓库根目录用下列工具调用，凭证只在容器内读取：

```powershell
python hm-ai-service/evaluation/knowledge_publication.py current
python hm-ai-service/evaluation/knowledge_publication.py publish --file hm-ai-service/src/main/resources/knowledge/customer-service-v1.json --if-match 0
```

首次未初始化时ETag是`"0"`，查询端知识不可用。后续每次发布必须先读取`current`，用返回的完整`generation-revision`替换`--if-match 0`；服务端拒绝通配覆盖。发布返回409时重新审核当前状态，422表示候选不合法，413表示超出1MiB，503或确认超时需要先读取当前状态确认结果，不能自动覆盖重试。

候选在事务前完成整个清单、ACL与已声明规则校验。事务内按命名空间串行化发布，核对ETag、绑定不可变文档版本、追加完整快照，再切换当前指针；任一步失败全部回滚，上一份有效发布继续使用。完整当前文档集可直接用于受权限约束的关键词检索；向量批次异步准备，未就绪时不读取上一版向量正文。该取舍保证知识生效不依赖外部Embedding可用性，向量召回可能暂时降级。

发布标签在共享模式下绑定原始文件SHA-256，不能复用标签提交不同字节。文档ID与文档版本还绑定规范JSON摘要，覆盖正文、标题、关键词、来源、ACL与规则；JSON对象属性顺序和格式空白不改变文档摘要，数组顺序仍属于内容。改正文或权限必须增加文档版本，跨历史发布也不能复用旧版本偷换内容。

回滚时以当前ETag重新提交审核后的旧快照，会得到新的generation；即使正文SHA回到旧值，也不能让旧请求的ETag再次有效。回滚恢复的权限同样需要审核；明确撤回的资料不能未经审核重新恢复。当前管理工具只处理已知文件，不提供正文历史导出或通用审批界面。

```json
{
  "version": "release-20261021",
  "documents": [
    {
      "id": "public-login",
      "version": "2",
      "status": "PUBLISHED",
      "title": "登录凭证",
      "keywords": ["登录", "凭证"],
      "content": "这里填写审核后的公开原文。",
      "source": "平台登录说明",
      "access": {"visibility": "PUBLIC"}
    },
    {
      "id": "internal-login",
      "version": "1",
      "status": "PUBLISHED",
      "title": "内部登录说明",
      "keywords": ["内部登录"],
      "content": "这里填写经批准的内部原文。",
      "source": "内部手册",
      "access": {"visibility": "RESTRICTED", "roles": ["ADMIN"], "userIds": [7]}
    }
  ]
}
```

`version`是发布标签；实际索引命名空间为`标签@整个文件的SHA-256`。文档有独立`version`。共享发布会拒绝已绑定版本的内容变化；显式文件模式通过新指纹阻止旧索引成为当前证据。标签及文档ID/版本只允许字母数字起始、后续字母数字或`._-`，最长80字符。

同一逻辑文档ID只能有一个`PUBLISHED`版本。旧版本可标`RETIRED`，待审版本用`DRAFT`，这两种状态不进入检索。同一ID多个发布版本会拒绝整份清单，不能按向量分数、排列顺序或模型判断选择规则。不同ID可通过下述规则声明检查现行取值是否一致；未声明的任意自然语言矛盾仍需发布审核。

发布文档必须明确声明`access`。`PUBLIC`不能同时指定授权名单；`RESTRICTED`的`roles`与`userIds`按并集授权，空名单无人可读。当前可信角色只有`USER`和`ADMIN`；没有隐式管理员全库权限，也不支持模型提供角色、部门字段或SSO组织关系。示例的用户7只是说明格式，实际部署必须使用真实授权账号。

缺少内容、访问策略、非法字段/标识/状态、重复JSON键、尾随JSON及超过1MiB的发布文件都会拒绝。文本字段不接受数字或布尔值自动转换；`visibility`只接受`PUBLIC`或`RESTRICTED`字符串，数字枚举序号及其文本形式均拒绝。共享模式拒绝无效候选并保留有效发布；当前数据库快照缺失、损坏或不可读取时知识查询停止，不能回退本地旧文件或旧权限。显式文件模式读到坏文件时也停止知识查询。文件路径与写入权限属于部署管理范围；发布管理只面向持有专属凭证的可信操作者。

位置与操作问题需要对应的依据：正文应写清页面、入口或实际步骤，并让它们与同主题处于同句说明。当前已识别场景缺少这些内容时，`missingDetails`报告“查看位置”或“操作步骤”；相关功能介绍仍可能不足以完成问题。排序原理、概念区别和数值政策分别核对，位置指引也不能代替费用或时限。

每份来源应贡献当前已识别的主题、字段或必要事实。登录介绍不等于退出后的状态规则，普通下单介绍不等于同一用户同一张券的次数限制，笔记介绍不等于排序依据。互补资料保留；点名多个店铺字段却仅覆盖部分时，保留已知来源并列出缺失字段。没有可用来源不能返回COMPLETED。

金额含义问题需要定义依据，不能只列字段名或两个数字。购买金额对应买券时支付的价格，抵扣金额对应按使用规则可抵扣的金额；只有一个定义时保留其来源并返回PARTIAL，列出“购买金额含义”或“抵扣金额含义”缺失。普通字段展示题仍可由字段列表回答。

操作说明由发布者结合实际界面、接口及部署版本审核维护；页面或行为变更时更新文档版本、发布指纹和正反例。当前内置v7中的登录、探店、优惠券说明文档版本均为2。这些检查是有限必要条件，尚未建立UI版本与清单的强制绑定，也不自动证明完整流程可执行。

## 不同文档的规则声明

发布文档可声明`effectiveFrom`、`effectiveUntil`与`shopIds`，例如：

```json
{
  "effectiveFrom": "2026-10-23T00:00:00+08:00",
  "effectiveUntil": "2026-11-01T00:00:00+08:00",
  "shopIds": [21]
}
```

时间按`[effectiveFrom, effectiveUntil)`执行，开始时刻有效、结束时刻失效。必须是带UTC或明确偏移量的完整ISO时间，不能填写无时区日期、空串、数字或布尔值；同时填写时结束必须晚于开始。未填写的边界表示发布者声明该方向无时间限制，`shopIds`未填或为空表示平台范围；非空只能包含正整数门店ID。元数据参与文档版本摘要，变更同样必须增加文档版本。

门店范围约束资料的适用对象，与`access`阅读权限独立；知道门店ID不授予受限资料访问权。知识服务只允许调用方使用服务端已确认实体作为查询范围，未知范围只能使用平台资料。当前客服入口的FAQ仅查询平台知识，浏览页或历史实体不能把特定门店政策套入平台问题；具体券规则由交易工具核对。当前不自动推断任意自然语言适用对象、历史订单或未来交易应适用的规则。

读取先按服务器UTC时钟、查询范围与ACL过滤，再进行向量召回／关键词回退；外部重排前和证据返回前都重新检查。即使发布指纹没有改变，生成途中到期的来源也会撤去。完整发布内的未来资料会预先建立向量，跨时间边界不依赖重新发布、重新Embedding或后台定时任务。规则判断依赖结构化声明与服务端时钟，不声称解决跨主机时钟漂移或正文中未标注的时间语义。

发布者可以在文档中填写可选`rules`。它用于发布一致性检查，不改变原有`access`权限，也不自动判断用户是否属于某个业务范围：

```json
{
  "id": "standard-transfer-policy",
  "version": "2",
  "status": "PUBLISHED",
  "title": "普通券转赠政策",
  "keywords": ["普通券", "转赠"],
  "content": "普通代金券禁止转赠。",
  "source": "经审核的转赠政策",
  "access": {"visibility": "PUBLIC"},
  "rules": [
    {
      "key": "voucher.transfer",
      "scope": "voucher.standard",
      "value": "denied",
      "quote": "普通代金券禁止转赠。"
    }
  ]
}
```

`key`定义规则维度，`scope`定义精确的适用范围；两者使用小写字母起始、后续小写字母数字或`._-`，最长80字符。`value`为发布方约定的规范取值字符串，使用与文档版本相同的标识格式，区分大小写。时间、金额等值须统一单位与含义；预计时间和最迟承诺应使用不同规则键，不应以同一键比较。`quote`必须是该文档正文中的非空连续原文片段，未知字段或缺少必要字段拒绝。

所有`PUBLISHED`文档中，同一`key + scope`的不同`value`，只有在文档生效区间与门店范围同时重叠时才冲突。相邻的半开时间区间、不重叠的门店集合可以有不同值；平台范围与任意门店范围相交。不同ID的文档可声明相同值，正文改写不影响规范值比较；不同规则scope仍分别核对。同一逻辑文档ID在一份清单中依然只能有一个PUBLISHED版本。冲突候选在共享发布激活前拒绝；显式文件模式读取冲突清单则不可用。不能让模型、排列顺序或相关性分数选边，草稿和退役文档不参与比较。

发布格式或规则冲突时FAQ报告`KNOWLEDGE_UNAVAILABLE`，独立业务查询仍可执行；修正发布或退役冲突文档后无需重启恢复。若生成期间出现冲突，返回前复核会撤去该轮旧FAQ证据。规则元数据也参与整个文件指纹，不能只改声明却继续沿用旧发布。

规范规则键、范围、单位和取值由可信发布者审核维护；原文片段存在不证明其语义必然等于所填取值。`rules`可省略，原有叙述资料仍能发布，但这类未声明的冲突没有结构化一致性保证。当前没有通用自然语言矛盾识别、自动规则抽取或适用范围推断；模型自报规则不能代替该发布契约。

## 显式文件模式（仅离线或受控验证）

在保留现有模型与服务环境变量的部署终端，指定可信目录后启用挂载：

```powershell
$env:HMDP_AI_KNOWLEDGE_DIR = 'C:/path/to/private-knowledge'
docker compose -f docker-compose.yml -f deploy/knowledge-publication.compose.yml up -d --no-deps --no-build ai-service
```

首次启动前该目录必须已有完整的`publication.json`。不要把真实内部正文或凭据提交到Git。挂载目录而不是单个文件，应用只读；发布者在同一目录准备、审核完整的`publication.next.json`后原子替换。Windows目标文件已存在时可使用：

```powershell
$publishedDirectory = [System.IO.Path]::GetFullPath($env:HMDP_AI_KNOWLEDGE_DIR)
[System.IO.File]::Replace(
  [System.IO.Path]::Combine($publishedDirectory, 'publication.next.json'),
  [System.IO.Path]::Combine($publishedDirectory, 'publication.json'),
  [System.IO.Path]::Combine($publishedDirectory, 'publication.previous.json'))
```

不要原地逐段改写正在读取的文件。应用每次获取本地文件都会检查字节指纹；格式损坏、版本冲突时FAQ报告`KNOWLEDGE_UNAVAILABLE`，独立的实时查询仍可返回。修复为合法清单后无需重启即可恢复。当前未提供独立发布前验证CLI或审批工作流。

文件更新后立即以新清单校验访问权限、来源及正文。开启`MILVUS_AUTO_IMPORT=true`及向量RAG后，启动时同步一次，并默认每15秒检查当前发布（`HMDP_AI_KNOWLEDGE_SYNC_INTERVAL_MS=15000`）。新指纹没有就绪索引时，只在当前授权文档中使用关键词回退；后台完整构建后自动恢复向量召回，无需重启。

每次构建使用独立`indexBuild`，查询同时过滤发布指纹、就绪批次和可读文档ID。Redis键`ai:knowledge:index:{集合名}:ready:发布指纹`保存已就绪批次UUID。向量数量、存储确认数量/唯一ID及当前发布均须通过检查，才能按租约所有者原子写入就绪指针；知识检索使用强一致性读取。部分写入、旧批次和未就绪数据不能提前参与检索。

同集合构建采用30秒共享租约。失败按发布指纹共享30秒起、最多5分钟的指数退避，轮询间隔还可能增加等待；新发布不继承旧发布的失败冷却。实例宕机后租约可到期，旧任务无法启用结果或释放新任务的锁。Redis不可用时不启动无协调的构建，查询仅使用当前授权关键词。失败不等于允许读取旧版本，关键词回退也不证明语义召回已经就绪。

已明确未发布的失败批次按其发布指纹和批次ID清理；发布确认超时则保留状态不明的数据，避免误删可能已经就绪的批次。进程崩溃或写入确认不明可能留下孤立数据，当前没有全量孤立批次回收器。周期同步解决索引追赶，不提供多台主机各自发布文件之间的一致性；生产多副本发布仍需共同的权威发布源。

回滚同样是发布一个明确清单；它可能恢复旧权限，需按真实政策处理。已就绪的旧索引保留用于回滚/审计，不意味着普通查询可访问历史版本。当前没有自动历史索引保留期策略。

## 一轮回答中的检查

受限知识还要求当前HTTP令牌在Redis登录态中绑定网关已认证的同一用户。请求开始时的身份快照不能延长已退出、过期或不可确认的会话；缺请求上下文、令牌缺失、用户ID不一致或Redis故障时不授予受限权限。角色继续来自可信网关，不读取登录Hash中的自报角色。该检查不刷新登录TTL，不将令牌存入DTO、模型数据、会话历史或异常日志。

纯公开清单无需新增登录态查询。混合清单在检索及重排前重新计算可读集合；生成前和提交前沿用现有证据复核。较晚阶段的整组证据失效仍可能撤去整个FAQ组，不能把独立公开题的通过推广为所有混合回答的最小失效粒度。可信发布任务的后台索引构建仍处理完整清单，这不是用户读取权限入口。

1. 网关清除外部伪造的用户/角色/内部令牌头，AI读取可信登录上下文；受限读取另确认活动令牌与该用户一致。
2. 当前发布清单计算可读文档集合，只在存在有效就绪指针时，按发布指纹、批次及文档ID过滤Milvus查询。
3. 对返回结果再次核对当前权限、发布指纹、文档版本及有限分数；实际证据正文从清单取，忽略索引正文。
4. 外部重排与回答模型只接收经过上述检查的候选；生成前再次确认清单及权限。
5. 模型逐题提交候选来源ID。代码核对来源白名单、协议、必要主题及已定义细节，按发布原文展示，不接收模型补写的FAQ正文。时限、费用、保证及使用限制需要对应事实，部分覆盖保留支持的来源，不能将相关主题直接标成完成。
6. 返回与提交前复核已选证据；发布变化、文档撤权或登录撤销使失效的FAQ证据降为`UNKNOWN / KNOWLEDGE_CHANGED_OR_ACCESS_REVOKED`，已核实的其他业务子任务保留。

API的`evidence`包含实际采用的`documentId`、`title`、`documentVersion`与`publicationVersion`；没有所需依据、未授权或失效来源没有引用。`faqAnswers`按题报告状态、原因与`missingDetails`；一题只有部分细节得到支持时返回PARTIAL，全部缺少依据则UNKNOWN。`task.requestId`可关联检索模式、来源检查与提交日志；日志不记录私有正文。

历史FAQ答复不再作为自由文本重放给模型，也不写入脱离权限与版本的历史向量。Redis仍保留用户已收到的会话记录；此措施不能收回已经发给用户或模型的副本。最终检查之后仍存在并发更新窗口，多副本独立文件也没有线性一致性保证。当前角色是请求时的可信身份快照，未实现组织授权撤销广播。

## 证据准确性的剩余边界

低分/非法向量、过期索引、伪造ID和已知不覆盖主题会被拒绝。已定义细节检查区分“去哪里查看进度”与到账时限、预计时限与保证、退款金额与费用，缺失项明确返回。向量相似度与重排分数不是正确率；来源存在、版本正确、用户可读，仍不证明它足以回答任意问题。当前有限词法检查不能解决任意改写、适用对象或条件不同、多个文档互相矛盾等全部情况。

当前`COMPLETED`表示通过已定义的来源选择与必要检查，不能视作通用语义证明。高要求知识库还需要基于真实资料的可回答性标注、反例评审及独立评测；无法证明的事实必须保留未知，不能用模型自报置信度补齐。组织目录、完整审批界面、任意业务范围推断与通用语义验证尚未完成；共享发布和时间／门店元数据的状态须以各阶段实际测试和部署记录为准。
